# وَصل — WASL | نسخة MVP للتجربة الداخلية والإنترنت

**الحالة:** إصدار تطويري تجريبي `0.9.0`، للاختبار ببيانات اصطناعية فقط. **ليس نظاماً معتمداً للاستخدام السريري الفعلي.**

## ما الذي يعمل فعلياً؟

- خادم FastAPI مع PostgreSQL في Docker (أو SQLite للتطوير الفردي فقط).
- حساب دخول شخصي لكل طبيب وكلمة مرور Argon2، وجلسات مخزنة في الخادم، وصلاحيات بحسب عضوية القسم.
- صندوق وارد وصادر خاص بالقسم، عدادات لوحة تحكم، وفلاتر حسب الحالة والطابق والأولوية والبحث.
- إنشاء استشارة بين مشافٍ وأقسام مختلفة، مع موقع المريض والسؤال السريري والجهة المسؤولة حالياً.
- رد طبي، استكمال معلومات، استقصاءات، طلب حضور المريض، إثبات الوصول والعودة.
- إحالة اختصاص فرعي لا تنقل مسؤولية الرد إلا **بعد قبول التحويل**.
- انتهاء الرد من القسم المسؤول، والإغلاق النهائي حصراً من القسم المرسل الأصلي.
- رفع PDF/JPG/PNG بحجم أقصى 8 ميغابايت، بتخزين غير عام والتحقق من صلاحيات تحميلها.
- دليل اتصال اختياري لكل قسم، وإثبات مكالمة ونتيجتها؛ والطباعة A4 مع وسم المسودة قبل الإغلاق.
- سجل أحداث لكل استشارة وسجل تدقيق تشغيلي أساسي، مع تجنب حذف الردود القديمة.
- شاشة مدير النظام لإدارة المشافي والمستخدمين والعضويات، وصلاحية **مسؤول مشفى** مستقلة لإضافة وتعديل وتعطيل أقسام مشفاه فقط.
- دليل اختصاصات هرمي (قسم رئيسي / قسم فرعي) يظهر مباشرة كوجهة للاستشارات. تعطيل القسم لا يمحو أرشيفه، وهو ممنوع مع استشارات مفتوحة أو أقسام فرعية نشطة.
- عرض عربي RTL يعمل على الهاتف؛ تحديث عدادات اللوحة كل 30 ثانية عند فتح التبويب.

## تشغيل سريع ببيانات اختبار عبر Docker

**المتطلبات:** حاسوب خادم يعمل باستمرار، Docker Engine + Docker Compose Plugin؛ شبكة داخلية (LAN) واتصال إنترنت عند الحاجة للتواصل عن بُعد.

1. فك الضغط في مجلد آمن، وادخل المجلد حيث `compose.yaml`.
2. انسخ `.env.example` إلى `.env` وغيّر `POSTGRES_PASSWORD` إلى كلمة طويلة عشوائية من أحرف وأرقام فقط؛ لا تستخدم كلمة المثال.
3. نفذ:

```bash
docker compose up -d --build
docker compose exec web python -m scripts.bootstrap
docker compose exec -it web python -m scripts.create_admin
docker compose ps
```

4. أنشئ أقسامك وحسابات أطباء الاختبار من واجهة المدير. يمكن لمدير النظام منح صلاحية «مسؤول مشفى» لأحد الحسابات، وبعدها يدير ذلك الشخص أقسام مشفاه فقط من «أقسام المشفى». أضف عضوية قسم لمستخدمك إذا رغبت بالتجربة السريرية الوهمية.
5. شغّل الوصول HTTPS الخاص عبر Tailscale كما في `NETWORK_DEPLOYMENT_AR.md`، ثم افتح العنوان المطبوع. مع `COOKIE_SECURE=true` **لا يعمل تسجيل الدخول عبر HTTP**؛ وهذا مقصود.
6. لإيقاف الخدمة: `docker compose down` (لا تستخدم `-v` لأنه يحذف بيانات القاعدة والمرفقات).

### تجربة سريعة على LAN، بمعلومات افتراضية **فقط**

غيّر في `.env`:

```ini
BIND_IP=0.0.0.0
COOKIE_SECURE=false
```

ثم نفذ `docker compose up -d --build`، وافتح على هاتف متصل بنفس شبكة الواي فاي:

```text
http://IP-OF-SERVER:8080
```

هذا **HTTP غير مشفر**؛ لا تستخدم عليه أي بيانات مرضى أو كلمات مرور حقيقية، ولا تفتح منفذ 8080 على الراوتر للإنترنت. استخدم حسابات تجريبية فقط. أعد `BIND_IP=127.0.0.1` و`COOKIE_SECURE=true` قبل اعتماد HTTPS.

### مستخدمو الاختبار (اختياري — لا ينفّذ على نظام حقيقي)

لا ينشئ `bootstrap` العادي أي مستخدم تجريبي. لإنشاء أربعة أطباء افتراضيين واستشارة افتراضية في **قاعدة تجارب منفصلة فقط**:

```bash
# على نسخة تطوير محلية فقط. كلمة المرور لا تستخدم خارج بيئة الاختبار.
DEMO_PASSWORD='MakeYourOwnDemoPassword2026!' docker compose exec -e DEMO_PASSWORD web python -m scripts.bootstrap --demo
```

المستخدمون: `obdoctor`، `internaldoctor`، `nephdoctor`، `cardiodoctor`. كلهم بكلمة `DEMO_PASSWORD`. **أزل بيانات الاختبار بالكامل قبل أي تشغيل مؤسسي، ولا تستخدم بيئة الاختبار للإنتاج.**

## تشغيل محلي للمبرمج دون Docker

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m scripts.bootstrap
python -m scripts.create_admin
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

الافتراضي SQLite وملف `wasl-dev.db`؛ مخصص لمبرمج واحد فقط، ولا يناسب العمل المتزامن الحقيقي بين المشافي.

## الاختبارات البرمجية

```bash
pip install pytest httpx
PYTHONPATH=. pytest -q
```

تحقق من `tests/test_workflows.py`: إرسال، صلاحيات، نقل مسؤولية، قبول/رفض التحويل، استكمال، إغلاق، حماية CSRF، المرفقات ودليل الهاتف. الاختبارات البرمجية **لا تعادل** اختبار سريري ولا اختبار اختراق أو اختبار اتصال فعلي بين مشافٍ.

## الملفات

- `app/main.py` — واجهة API وقواعد الصلاحية ومسار الاستشارة.
- `app/models.py` — بنية بيانات SQLAlchemy.
- `app/static/` — الواجهة العربية RTL بدون اعتمادات JavaScript خارجية.
- `app/report.html` — التقرير القابل للطباعة.
- `scripts/bootstrap.py` — تأسيس المشافي والأقسام (من دون بيانات مرضى).
- `scripts/create_admin.py` — إنشاء مدير النظام تفاعلياً.
- `compose.yaml` — حاويتان: الخادم وقاعدة البيانات؛ قاعدة البيانات غير مكشوفة للعامة.
- `NETWORK_DEPLOYMENT_AR.md` — التشغيل داخل الشبكة وعلى الإنترنت.
- `SECURITY_BEFORE_CLINICAL_LAUNCH_AR.md` — ما يلزم قبل بيانات المرضى.

## حدود النموذج الحالية

لا توجد تنبيهات Push موثوقة للأطباء وهم خارج التطبيق، بل تحديث للوحة أثناء فتح الصفحة؛ لا يوجد تكامل EHR أو HL7 FHIR أو هوية مريض بين المشافي؛ ولا جدولة مناوبات، ولا موافقات/توقيعات إلكترونية قانونية، ولا تتبع انتظار زمني رسمي للتأخير. تقرير HTML قابل للطباعة أو الحفظ PDF من المتصفح، **وليس ملف PDF موقّعاً إلكترونياً**. دعم ترحيل قاعدة البيانات Alembic، والنسخ الاحتياطي التلقائي المشفر، والفحص الأمني للمرفقات، والمراقبة المركزية والتدقيق غير القابل للعبث، كلها **مطلوبة قبل أي تشغيل سريري**.

## إدارة الأقسام ديناميكياً (v0.5)

- ينشئ مدير النظام حساب مسؤول المشفى ويمنحه إدارة مشفى محدد من واجهة الإدارة.
- يختار مسؤول المشفى «أقسام المشفى» ثم يضيف القسم الرئيسي أو فرعاً تابعاً لقسم موجود في نفس المشفى.
- يمكن تغيير اسم القسم دون تغيير رقمه الداخلي أو استشاراته السابقة.
- تعطيل القسم يمنع اختياره لطلبات جديدة، لكنه لا يحذف السجل. لا يسمح بتعطيل قسم عليه استشارات مفتوحة أو فروع نشطة.
- الإضافة وحدها **لا** تنشئ حساب طبيب أو تمنحه صلاحية الاطلاع؛ مدير النظام يربط عضويات الأطباء بالأقسام الجديدة بشكل منفصل.
- متطلبات ما قبل الإنتاج: مراجعة migrations ونسخ احتياطي، تدقيق أمني، سياسات تتبع التغييرات والموافقة المؤسسية.


## تحديث V0.9 — اليوم الطبي / تسليم المناوبة / الأرشيف / الإشعارات الداخلية

- يعتبر اليوم الطبي من 09:00 صباحاً إلى صباح اليوم التالي 09:00 (الحد الأعلى غير مشمول)، وفق `CLINICAL_TIMEZONE=Asia/Damascus`؛ **التوقيت الزمني يُحسب على الخادم دون إعادة ضبط بيانات الاستشارات أو تنفيذ مهمة مجدولة الساعة التاسعة**.
- صفحة القسم تعرض عدادات المنشأ اليوم والمرحّل من أيام سابقة والمغلق اليوم، إلى جانب مؤشرات الواردة والصادرة القديمة.
- الاستشارات المفتوحة أو التي انتهى رد المستقبِل عليها دون إغلاق المرسِل تظل ظاهرة وقابلة للعمل عبر الأيام.
- الأرشيف هو الاستشارات بحالة `closed` فقط، ويعرض الصادرة والواردة وفق الصلاحيات؛ تبقى قابلة للقراءة وطباعة A4، دون حذف سجلاتها.
- صفحة تسليم المناوبة تعرض الاستشارات الأقدم من بداية اليوم الحالي وغير المغلقة، مع توضيح الجهة التي يقع عليها الإجراء.
- إشعارات **داخل التطبيق فقط** ومرتبطة بالقسم وهوية المستخدم؛ لا تحتوي نصاً طبياً أو هوية مريض، ويمكن تعليم كل إشعار كمقروء.
- Web Push عندما يكون الموقع مغلقاً، التذكيرات/التصعيد التلقائي، نظام الرسائل المضمون، وإعدادات الاشتراك للأجهزة **ليست منفذة بعد**. يجب ألا يعتمد الأطباء على التنبيهات الإلكترونية للحالات الإسعافية قبل الاختبار السريري.
- لا توجد حاجة لتمرير أو حذف استشارات عند الساعة 09:00؛ إعادة التجميع تتحقق حتى عند توقف الخادم أو إعادة تشغيله.

### التحديثات الإضافية في API

`GET /api/dashboard` يعيد مجموعة `clinical_day`، و`GET /api/consultations?scope=open|today|carryover|archive|all`، و`GET /api/handover`، و`GET /api/notifications`، و`POST /api/notifications/{id}/read`. تتحقق جميعها من عضوية القسم على الخادم. توجد 12 تجربة API آلية ناجحة، لكنها لا تمثل اختبار أمن إنتاجي.
